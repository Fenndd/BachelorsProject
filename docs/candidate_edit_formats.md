# Candidate Edit Formats

## Purpose

Raw unified diff is fragile as an LLM output format. LLMs may propose reasonable code changes but fail to produce machine-applicable patches because of wrong hunk headers, line counts, or context. The project therefore separates semantic optimization from mechanical application through the **Candidate Edit Format Layer**.

Candidate format is selected by `candidate_format` in experiment config and passed to `orchestrator.llm.generate_candidate` as `--candidate-type` and `--source-presentation`.

## Supported Formats

### `unified_diff`

- Legacy format.
- `candidate_type`: `unified_diff`
- `schema_version`: `1.0`
- Source presentation: `plain`
- Artifact: `candidate.diff`
- Materialization: `git apply`
- Fallback: `git apply --recount` for malformed hunk counts when Git can infer the correct counts.
- Still supported for backward compatibility and fallback experiments.

### `line_range_edits`

- Preferred robust format for real LLM full-cycle experiments.
- `candidate_type`: `line_range_edits`
- `schema_version`: `1.1`
- Source presentation: `line_numbered`
- Artifacts:
  - `candidate.json`
  - `candidate.edits.json`
  - `candidate.generated.diff` after materialization
- The LLM returns `edits[]` with:
  - `file`
  - `start_line`
  - `end_line`
  - `original`
  - `replace`
- `original` must not include the line-number prefix from the prompt.
- The materializer verifies actual source text before applying.
- Exact-search fallback is strict and only succeeds if `original` occurs exactly once.
- The diff is generated by the system, not by the LLM.

## Config

Preferred line-range format:

```json
{
  "candidate_format": {
    "type": "line_range_edits",
    "source_presentation": "line_numbered",
    "require_original_verification": true,
    "allow_exact_search_fallback": true
  }
}
```

Legacy unified-diff format:

```json
{
  "candidate_format": {
    "type": "unified_diff",
    "source_presentation": "plain",
    "require_original_verification": true,
    "allow_exact_search_fallback": true
  }
}
```

## Materialization Flow

For `unified_diff`:

```text
candidate.json + candidate.diff
  -> git apply --check
  -> optional git apply --check --recount
  -> workspace patch
```

For `line_range_edits`:

```text
candidate.json + candidate.edits.json
  -> copy workspace
  -> verify line ranges
  -> apply edits
  -> generate candidate.generated.diff
```

## Recommendation

Use `line_range_edits` for real LLM full-cycle experiments. Keep `unified_diff` as a legacy/fallback format.
